# Deriving optics

`@DeriveOptics` reads a type declaration and generates the operations used by
`@f`. Import both `lucida.*` and `lucida.macrodsl.*` in code that uses the
resulting paths.

## Structs and classes

```cangjie
@DeriveOptics
public struct Position {
    public Position(public let x: Int64, public let y: Int64) {}
}
```

The macro generates a lens for each field declared in the primary
constructor. For `x`, the read accesses `source.x`; the replacement constructs
`Position(focus, source.y)`.

```cangjie
let position = Position(2, 3)
let moved = @f(position.x <- 8)
let x = @f(@ty(Position).x)
```

`moved` is `Position(8, 3)`, and `x` is a `Lens<Position, Int64>`.
The same derivation is available for a class with a suitable primary
constructor. Updating a class reconstructs it by calling that constructor;
it does not assign to the old instance.

The current derivation has these requirements:

- A primary constructor must be present.
- Every primary-constructor parameter must declare a field with `let` or `var`.
- Those fields must not be private.
- Generic `where` constraints are not supported.

Public constructor fields receive public optic members. Other accepted field
visibilities receive package-visible members. The macro uses the primary
constructor's field list, not every property or variable declared in the body.

Constructor behavior matters. Additional state initialized by a constructor
will be initialized again during reconstruction. Derived optics do not promise
a deep clone of class instances or mutable field values.

## Enums

```cangjie
@DeriveOptics
public enum Job {
    | Waiting
    | Running(Int64)
    | Failed(Int64, String)
}
```

Each case receives an affine optic. Its read checks the case, and its update
preserves sources belonging to another case.

| Case | Focus type | Read result |
|---|---|---|
| `Waiting` | `Unit` | `Option<Unit>` |
| `Running(Int64)` | `Int64` | `Option<Int64>` |
| `Failed(Int64, String)` | `(Int64, String)` | `Option<(Int64, String)>` |

```cangjie
let job = Job.Failed(7, "Connection lost")
let changed = @f(job?.Failed <- (8, "Retry failed"))
let message = @f(job?.Failed._1)
```

`message` is `Option<String>`. Tuple element paths use `._0`, `._1`, and so
on. A payloadless case uses `()` when a replacement focus is needed; updating
through it still preserves other cases.

## Generic records

```cangjie
@DeriveOptics
public struct Box<T> {
    public Box(public let value: T) {}
}
```

```cangjie
let box = Box<Int64>(5)
let changed = @f(box.value <- 9)
let value = @f(@typeof(box).value)
```

The resulting lens has type `Lens<Box<Int64>, Int64>`. The replacement keeps
that type; it cannot turn this `Box<Int64>` into a `Box<String>`.

For a constrained generic type, construct an optic value yourself or provide
a suitable unconstrained declaration. The macro currently rejects `where`
clauses instead of propagating their constraints to generated declarations.

## One-field wrappers

A record with exactly one constructor field also receives an iso between the
record and that field's type:

```cangjie
@DeriveOptics
public struct Meters {
    public Meters(public let value: Int64) {}
}
```

```cangjie
let distance = Meters(7)
let number = @f(distance.coerce<Int64>())
let changed = @f(distance.coerce<Int64>() <- 12)
```

`number` is `7`, and `changed` is `Meters(12)`. `coerce<T>()` uses the
registered conversion for those types; it is not a general Cangjie cast.
The derive emits both conversion directions. A type with several fields
has no such automatic conversion because rebuilding it would require the
other field values.

Use `.` before `coerce`: an iso's forward conversion is total. `coerce` is
a reserved slot name inside `@f`.

## Tuples

Tuple optics are already generated by the core library for arities 2 through
16; no annotation is required:

```cangjie
let pair = ("Ada", 7)
let changed = @f(pair._1 <- 8)
let values = @f(pair.{ ._0; ._1 })
```

The element number is zero-based and must exist in the tuple's arity. This
path syntax differs from Cangjie's ordinary tuple indexing syntax.

For behavior that cannot be derived from a constructor, see
[custom optics](user-optics.md).
